## 1. Пункт 2 ТЗ делаем, а не описываем (01.10.2026, Павел)

**Что решено.** Пункт 2 «Подключение обычного Telegram» входит в MVP.

**Почему.** В ТЗ он помечен «если успеваете». Обязательные пункты сделают все кандидаты, а работающий пункт 2 отличает решение. Для агентства это тоже реальная потребность: часть клиентов пишет менеджеру в личку, а не боту.

## 2. Пункт 2 через Telegram Business, на отдельном аккаунте (01.10.2026, Павел)

**Формулировка Павла:** «Отдельный аккаунт, он у меня уже есть, SIM не нужна. Основной не подключаем.»

**Что решено.** Бот подключается к рабочему аккаунту как чат-бот Telegram для бизнеса и получает апдейты `business_message` тем же webhook, что и анкета. Telegram Premium для этого не нужен с Bot API 10.0 (08.05.2026).

**Почему не user-клиент (Telethon).** User-клиенту нужен постоянный процесс с MTProto-соединением и файл сессии с полным доступом к аккаунту. Ещё есть риск ограничений аккаунта за вход с IP дата-центра. Business-подключение официальное, отключается в настройках Telegram одной кнопкой и даёт боту доступ только к выбранным чатам.

## 3. Получатели Business: только «Новые чаты» (01.10.2026, Павел)

**Формулировка Павла:** «Фильтр Business, там типы чатов в „Получателях“, скорее всего, складываются через ИЛИ, тогда „новые“ + „не из контактов“ захватят старые чаты с незнакомцами. Проверь и, если так, оставляем только „Новые чаты“. До включения пункта 2 проверить руками, что старый чат не создаёт лид.»

**Что проверено.** В документации `inputBusinessBotRecipients` каждый флаг описан как «Selects all ...», а `exclude_selected` как «all private chats except the ones selected by existing_chats, new_chats, contacts, non_contacts and users». Это объединение, то есть ИЛИ.

**Что решено.** Получатели: только «Новые чаты». Ручная проверка «старый чат не создаёт лид» стоит в плане до включения пункта 2 в работу.

## 4. Стенд: Render free + Neon + внешний пинг (01.10.2026, Павел)

**Формулировка Павла:** «На домен тратиться не хочу, а *.vercel.app из РФ не открывается (проверил, onrender.com отвечает). Регистрацию в Render через VPN сделаю сам. /healthz для пинга пусть не трогает базу.»

**Что решено.** Один процесс FastAPI на Render free (Frankfurt), база Neon Postgres free, UptimeRobot пингует `/healthz` каждые 5 минут, потому что Render засыпает через 15 минут без трафика. Своих VPS под проект нет, платные тарифы не используем.

**Почему `/healthz` без базы.** Neon free даёт 100 CU-часов в месяц. Если пинг будет трогать базу, compute не уснёт никогда: 0.25 CU × 744 ч ≈ 186 CU-ч, лимит кончится к середине месяца.

**Альтернативы.** Vercel не открывается из РФ без VPN. Always-on VM (Oracle, GCP) требует карту. Бесплатного always-on хостинга без карты на 01.10.2026 не нашлось.

**Проверка доступности.** Павел проверяет стенд со своего IP и с мобильного интернета: после первого деплоя и перед сдачей.

## 6. Сверх ТЗ: источник по deep link, уведомление в группу, статусы и «ждёт N мин» (01.10.2026, Павел)

**Что решено.** Ссылка `t.me/<bot>?start=<кампания>` ставит лиду тег кампании. Новый лид сразу уходит в группу менеджеров. У лида есть статус, а пока он новый, в списке видно, сколько он ждёт ответа. Экспорт CSV не делаем.

**Почему.** Агентство платит за трафик и должно знать, какая кампания дала заявку. Лид остывает за минуты, поэтому важна скорость реакции.

## 10. База Neon остаётся в us-east-2, подключение напрямую, без пулера (01.10.2026, Павел; пересмотрено в решении 11)

**Что выяснилось.** Проект Neon создан в us-east-2 (Огайо), а Render стоит во Frankfurt. В строке подключения был адрес пулера (`-pooler`).

**Варианты, которые были на столе.** Пересоздать Neon во Frankfurt (около 5 минут у Павла); оставить Огайо; перенести Render в Огайо (новый сервис, новый URL, повторная проверка доступности из РФ).

**Что решено (выбор Павла).** Оставить Огайо, подключаться напрямую, без пулера.

**Цена.** По оценке, плюс около 100 мс на каждый запрос к БД, на одно сообщение боту их 5-10. Это оценка, а не замер: замер задержки на стенде стоит в G2.

**Почему без пулера.** Пулер Neon это PgBouncer в transaction mode, он конфликтует с prepared statements, которые использует asyncpg.

## 11. Стенд и база в одной локации: новый Neon во Frankfurt (01.10.2026, Павел)

**Формулировка Павла:** «Давай все-таки в одну локацию.»

**Варианты.** Новый проект Neon во Frankfurt (Render и его URL не меняются, база пустая, переносить нечего) или пересоздание Render в Огайо (новый URL, повторная проверка доступности из РФ).

**Что решено.** Новый проект Neon в AWS eu-central-1, прямое подключение без пулера. Причина отказа от пулера из решения 10 остаётся в силе.
