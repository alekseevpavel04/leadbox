# Leadbox

Мини-CRM для агентства. Лиды из анкеты Telegram-бота и из лички подключённого рабочего аккаунта попадают в неё сами, остальных менеджер заводит руками. Тестовое задание на позицию «Вайбкодер» в Jump Ads (срок три дня) и проект для портфолио.

## Как проверить за 2 минуты

1. Напишите боту по ссылке с меткой кампании: [t.me/leadbox_demo_bot?start=jumpads_review](https://t.me/leadbox_demo_bot?start=jumpads_review). Бот спросит имя, контакт и запрос, покажет сводку, нажмите «Отправить».
2. Откройте CRM: [leadbox-ov2n.onrender.com](https://leadbox-ov2n.onrender.com), логин `demo`, пароль `leadbox-32b017`.
3. Ваш лид первый в списке, с тегами `бот` и `кампания:jumpads_review`. Список обновляется сам раз в 10 секунд. Клик по тегу оставляет только лидов с этим тегом.

Лид создаётся уже после /start, поэтому брошенная анкета тоже видна, с пометкой «анкета не завершена». Ввод можно ломать: стикер вместо имени, `12345` вместо телефона, /start посреди анкеты, /cancel.

Лиды с тегом `демо` (7 штук) залиты скриптом `scripts/seed_demo.py`, чтобы список не был пустым. Время создания у них настоящее, то есть момент заливки. Уведомление о новом лиде уходит в группу менеджеров, её вижу только я, так что этот шаг проверяющему не виден. Личку снаружи тоже не проверить: рабочий аккаунт не публикуется. Как она проверена вживую, сказано в «Ограничениях».

Стенд стоит на бесплатном Render, который засыпает через 15 минут без трафика. UptimeRobot раз в 5 минут запрашивает `/healthz` и не даёт ему уснуть. Если пинг не успел, первый ответ бота после долгой тишины придёт позже обычного.

## Как устроено

![Схема: путь заявки от источника до менеджера](docs/img/scheme.png)

*Схема: заявка из бота (тег кампании из ссылки), из лички рабочего аккаунта или вручную становится лидом с тегами, на человека один открытый лид. Менеджеру сразу уходит уведомление, в CRM лид виден за 10 секунд, клик по тегу фильтрует список. Ответ в личке или смена статуса снимает «ждёт».*

Тот же путь в коде:

```
Telegram --webhook--> POST /tg/webhook --+
  бот: message, callback_query           |  FastAPI + aiogram, один процесс uvicorn
  личка: business_connection,            +--> services/ (лиды, теги) --> Neon Postgres
         business_message,               |
         edited_business_message         |
Браузер менеджера --> CRM (Jinja2, HTMX) +
после commit --> sendMessage в группу менеджеров
UptimeRobot --раз в 5 мин--> /healthz (без базы)
```

- **Render free во Frankfurt, Neon free там же** (`eu-central-1`), подключение напрямую. Пулер Neon работает как PgBouncer в transaction mode и конфликтует с prepared statements asyncpg. Vercel отпал: `*.vercel.app` из РФ не открывается, `*.onrender.com` открывается (решения 4 и 11 в [DECISIONS](docs/DECISIONS.md)).
- **Webhook** проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`, без верного секрета отвечает 403. `max_connections=1`: Telegram отдаёт апдейты по одному, и два быстрых нажатия одного человека не спорят за один лид.
- **Идемпотентность по `update_id`.** Номер апдейта пишется в `processed_updates` в той же транзакции, что и изменения лида. Повтор от Telegram (на холодном старте он вероятен) получает 200 и ничего не меняет.
- **Ответы и уведомления после commit.** Обработчики не вызывают Telegram сами: вызовы копятся в `Outbox` и уходят после commit. Ошибка базы получает 503, и Telegram повторит апдейт. Любая другая ошибка пишется в лог и получает 200: баг упал бы на каждом повторе и при `max_connections=1` держал бы очередь остальных.
- **Шаг анкеты в базе.** Лид создаётся сразу после /start, текущий шаг лежит в `leads.form_step`, FSM aiogram в памяти выключен. Рестарт сервиса ничего не теряет, брошенная анкета видна в CRM.
- **Один открытый лид на человека.** Новое обращение с того же Telegram id, из бота или из лички, дописывается в лид со статусом «новый» или «в работе» и получает тег своего источника. Уведомление в группу уходит по каждому лиду один раз, это помнит поле `notified_at` (решение 13).
- **Личка через Telegram для бизнеса** (решения 2 и 3). Бот подключён к отдельному рабочему аккаунту с правами только на чтение и сам в чаты не пишет. Получатели только «Новые чаты»: типы чатов в этой настройке складываются через ИЛИ, и «не из контактов» затянул бы старые переписки с незнакомцами. Входящее сообщение становится лидом с тегом `telegram`, в интерфейсе источник подписан «личка». Ответ владельца снимает отметку «ждёт».
- **`/healthz` не трогает базу.** Neon free даёт 100 CU-часов в месяц, а compute, которому пинг не даёт уснуть, съел бы 0.25 CU × 744 ч ≈ 186 CU-ч (решение 4).
- **CRM** на Jinja2 с автоэкранированием и HTMX (локальная копия). CSRF-токен на всех POST, сессия в подписанной cookie. Имена и запросы пишут посторонние люди, поэтому в уведомлениях в группу их поля проходят `html.escape` (решение 7).

```
src/leadbox/
  main.py       приложение: lifespan (база, бот), /healthz
  config.py     настройки из окружения, строка Neon под asyncpg
  models.py     таблицы, перечисления, подписи источников, лимиты полей
  services/     лиды, теги, служебные записи Telegram; бот и CRM ходят в базу только через них
  bot/          webhook.py, transaction.py (транзакция и Outbox), dialog.py (анкета),
                contact.py (телефон, @username, email), business.py (личка), notify.py, runtime.py
  crm/          routes.py, auth.py (вход, CSRF), templates/, static/
alembic/        миграции
scripts/        seed_demo.py, check_doc_limits.py
tests/          pytest на SQLite in-memory, Telegram подменён фейковой сессией
docs/           PRODUCT.md, REVIEW.md, DECISIONS.md, PROMPTS.md, img/
```

## Запуск локально

Нужны Python 3.11 и второй бот для разработки. В режиме polling приложение снимает с бота webhook, и с токеном стенда это отключило бы стенд. Поэтому без `DEV_BOT_TOKEN` оно не стартует.

```bash
python -m venv .venv                  # Python 3.11
. .venv/bin/activate                  # Windows: .venv\Scripts\activate
pip install -r requirements.txt       # точные версии, как на Render
pip install -e ".[dev]"               # пакет leadbox и pytest, ruff, aiosqlite, httpx
cp .env.example .env
```

Что заполнить в `.env`:
- `DATABASE_URL=sqlite+aiosqlite:///leadbox.db` (или строка Neon);
- `BOT_MODE=polling` и `DEV_BOT_TOKEN`, токен второго бота от @BotFather;
- `SESSION_SECRET`, `CRM_USER`, `CRM_PASSWORD`: без них CRM не стартует;
- `MANAGER_CHAT_ID`: id группы, куда добавлен dev-бот. Если оставить пустым, уведомления пропускаются с предупреждением в логе;
- `PUBLIC_BASE_URL`: адрес, на который ведут ссылки в уведомлениях (локально `http://127.0.0.1:8000`).

```bash
alembic upgrade head                  # миграции 0001 и 0002
python scripts/seed_demo.py           # 7 демо-лидов с тегом «демо»; повторный запуск ничего не делает
uvicorn leadbox.main:app --app-dir src
pytest -q                             # 283 теста, без сети
ruff check .
python scripts/check_doc_limits.py    # объём PRODUCT.md и REVIEW.md, длинное тире, подписи к картинкам
```

## Деплой

Стенд разворачивается из [`render.yaml`](render.yaml) как Render Blueprint: один бесплатный web-сервис во Frankfurt, Python 3.11.4.

- Сборка `pip install -r requirements.txt`, старт `alembic upgrade head && uvicorn leadbox.main:app ...`. У бесплатного тарифа нет pre-deploy команды, поэтому миграции идут при каждом старте; на актуальной схеме `upgrade head` ничего не делает.
- `BOT_MODE=webhook` задан в `render.yaml`. В панели Render вводятся `BOT_TOKEN`, `MANAGER_CHAT_ID`, `DATABASE_URL`, `PUBLIC_BASE_URL`, `WEBHOOK_SECRET`, `SESSION_SECRET`, `CRM_USER`, `CRM_PASSWORD`.
- `DATABASE_URL` это строка подключения Neon как есть, только без `-pooler` в адресе. `config.py` сам переводит её под asyncpg. С пустым `DATABASE_URL` приложение не стартует.
- Webhook приложение ставит само при старте, с секретом из `WEBHOOK_SECRET`.
- Личка: в @BotFather включить у бота Business Mode (сейчас пункт называется Secretary Mode), затем в рабочем аккаунте: Настройки, Telegram для бизнеса, «Автоматизация чатов», получатели только «Новые чаты», права только на чтение.
- UptimeRobot: HTTP-монитор на `/healthz` раз в 5 минут.
- Демо-данные: `python scripts/seed_demo.py` с `DATABASE_URL` стенда.

## Ограничения и что не сработало

- **Сценарий «старый чат не создаёт лид» вживую не проверен.** Чата, который существовал бы до подключения бота, у рабочего аккаунта не было. Этот сценарий обеспечивает настройка получателей в Telegram, код его не проверяет. Остальное по личке я проверил вживую 01.10: новое сообщение стало лидом с тегом `telegram`, уведомление пришло в группу, ответ с рабочего аккаунта снял «ждёт».
- **Бесплатный хостинг засыпает.** Если пинг не успел, первый апдейт ждёт старта сервиса. Telegram повторит его, если не дождётся ответа, а повтор отсечёт `update_id`.
- **Один демо-пользователь**, без ролей и без лимита попыток входа. Пароль сравнивается через `compare_digest`, но перебор ничем не ограничен.
- **Ответить клиенту из CRM нельзя.** Бот подключён к аккаунту только на чтение, менеджер отвечает в Telegram.
- **Длинный запрос.** Текст длиннее 4096 символов клиент Telegram делит на несколько сообщений. Бот отбрасывает хвост, если части пришли с разницей не больше 2 с. При паузе больше хвост проверяется как отдельное сообщение и может пройти как запрос; человек увидит его в сводке перед «Отправить».
- **Нетекстовые сообщения в анкете** (стикер, фото, голосовое) получают просьбу написать текстом и в историю лида не пишутся. В личке они записываются как `[фото]`, `[голосовое]` и так далее.

Что не сработало с первого раза:
- База сначала оказалась в us-east-2 при сервисе во Frankfurt, да ещё с адресом пулера. Я завёл новый проект Neon во Frankfurt, подключение напрямую (решения 10 и 11).
- Первый деплой рабочей версии упал на миграции. Из-за опечатки в имени переменной на Render `DATABASE_URL` был пуст, и конфиг молча подставил локальный SQLite. Опечатку исправил я, а молчаливый откат убрали из кода: на стенде он дал бы пустую базу, которая стирается при рестарте.
- Пункт меню для подключения бота лежит внутри раздела платной подписки «Telegram для бизнеса». Это выглядело как расхождение с разведкой («с Bot API 10.0 Premium не нужен»), но подключение прошло без оплаты.
- Проверка глазами проверяющего (стенд и код) нашла два серьёзных дефекта. Список лидов на телефоне был шире экрана, теги и «ждёт» уходили за край. Запрос на 5000 символов Telegram делит на 4096 и 904, хвост принимался как запрос, а тест проверял одно сообщение на 5000, какого Telegram не присылает. Оба исправлены, на хвост добавлены тесты с настоящим делением.
